# ScreenCraft 开发里程碑（milestones.md）

> 版本：v0.4。本文件是 Cursor 的**开发节奏与验收基准**：M0→M8 为 v0.3 历史基线；AI 智能样式编辑严格按 M9.0→M9.6 推进，一个里程碑内完成验收清单后才进入下一个；每个里程碑结束必须 git commit（建议每完成一个功能点即 commit）。
> 预估请求数为 Cursor Agent 快速请求的粗估，供额度管理参考（Pro 500 次/月）；实际以功能点拆分为准，超支 50% 以上时停下来与用户复盘。
> 依赖关系：M3 依赖 M1/M2；M4 依赖 M3；M5/M6 依赖 M4；M7 依赖 M5；M8 依赖 M4/M7。M9 依赖已完成的 M8；M9.0 是后续所有 M9 开发的硬门槛，M9.4 依赖 M9.1，M9.5 依赖 M9.3/M9.4，M9.5.1 依赖 M9.4，M9.6 依赖 M9.5/M9.5.1。

## M0 工程脚手架

**范围**：pnpm workspace 三包（frontend / backend / packages/shared）、TypeScript strict、ESLint + Prettier（可后置到任意里程碑补）、`.env` 加载、MongoDB 连接、种子脚本（初始化 admin/ScreenCraft@2026，首次登录强制改密标记）、Axios 统一封装骨架（get/post、token 注入、`{code,message,data}` 解包、401 跳登录、ElMessage 报错）。

**不做**：任何业务页面。

**验收清单**：
- [ ] `pnpm i && pnpm -r dev` 前后端均可启动；前端访问后端健康检查返回 200
- [ ] shared 包被前后端同时引用（一个类型 + 一个错误码常量即可验证链路）
- [ ] 种子脚本可重复执行（幂等：已存在则跳过）
- [ ] `.env.example` 全部变量在代码中有对应读取，无硬编码密钥
- [ ] Axios 封装单例就位，业务代码无法绕过（约定 + review）

## 通用纪律（每个里程碑适用）

1. 开工前：读 `.cursorrules` + 当前里程碑范围 + 对应 PRD 章节；先出简短实现方案（涉及哪些文件/接口）再动手。

3. 每个功能点完成即 commit；里程碑完成打 tag（m1、m2…）。
4. 遇到文档未覆盖的细节：**停下来问**，确认后回写文档，禁止猜。
